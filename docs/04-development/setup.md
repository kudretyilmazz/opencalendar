# Local Development Setup

How to run OpenCalendar on your machine for development.

Last updated: 2026-09-28

## Prerequisites

| Tool | Version | Why |
|---|---|---|
| Node.js | 24 (see `.nvmrc`; ≥ 22 supported) | Runtime for Next.js 16 and the worker |
| npm | 11+ | The lockfile is written by npm 11 |
| Docker + Docker Compose | recent | Local PostgreSQL + Mailpit, and Testcontainers for integration tests |

## 1. Install

```bash
git clone <repo-url> opencalendar && cd opencalendar
npm install
```

## 2. Start backing services

```bash
npm run services:up        # docker compose -f docker-compose.dev.yml up -d --wait
```

| Service | Host port | Purpose |
|---|---|---|
| `postgres` (16) | **5433** | Main database and the pg-boss job queue (5433 avoids clashing with a local Postgres) |
| `mailpit` | 1025 (SMTP), 8025 (UI/API) | Catches every outgoing email. Open http://localhost:8025 |

## 3. Configure

```bash
cp .env.example .env
# then fill the two secrets:
#   AUTH_SECRET=$(openssl rand -base64 32)
#   ENCRYPTION_KEY=$(openssl rand -base64 32)
```

`.env.example` is preconfigured for the dev services (`DATABASE_URL` on port 5433, SMTP to Mailpit, `SMTP_FROM`, `WORKER_MODE=inline`). Every variable is validated with Zod at startup (`lib/env.ts`); a bad value stops the process with a message naming each variable. Full reference: [self-hosting](../03-architecture/self-hosting.md#environment-variables).

## 4. Run

```bash
npm run dev                # http://localhost:3000
```

On startup `instrumentation.ts` → `lib/bootstrap.ts` validates env, applies migrations (`MIGRATE_ON_START=true`), and, with `WORKER_MODE=inline`, starts the pg-boss workers in the same process. To run the worker separately, set `WORKER_MODE=external` and run `npm run worker:dev`.

The first account you create becomes the instance admin. Verification, magic-link and password-reset emails appear in Mailpit.

## Scripts

| Script | Does |
|---|---|
| `dev` / `build` / `start` | Next.js (`build` also bundles `dist/worker.js` and `dist/cli.js` with esbuild) |
| `worker:dev` / `worker` | Background job worker (watch mode / bundled) |
| `lint` / `typecheck` / `format` | ESLint, `next typegen && tsc --noEmit`, Prettier |
| `test` / `test:unit` / `test:integration` / `test:coverage` | Vitest (integration starts a throwaway Postgres via Testcontainers) |
| `test:e2e` | Playwright against `http://localhost:3000` (reuses the dev server) |
| `db:generate` / `db:migrate` / `db:studio` | Drizzle migrations and studio |
| `services:up` / `services:down` | Dev Postgres + Mailpit |

E2E notes: set `E2E_DATABASE_URL` (or `DATABASE_URL`) so the Playwright global setup can clear rate-limit counters between runs; `E2E_BASE_URL` and `MAILPIT_URL` point the suite at another deployment.

## Next.js 16 notes

Read the bundled guides in `node_modules/next/dist/docs/` before using framework APIs ([AGENTS.md](../../AGENTS.md)). Specifics this codebase relies on are listed at the top of [implementation steps](./implementation-steps.md#nextjs-16-facts-we-rely-on). Route types (`PageProps<"/login">`) are generated by `next typegen`, which `npm run typecheck` runs first.

## Troubleshooting

- **Emails don't arrive:** check http://localhost:8025 and the server log for `email.sent` / `email.failed` events. Nothing reaches real inboxes in development.
- **"Too many requests" while testing:** sign-up and sign-in are rate-limited per IP. `DELETE FROM rate_limit;` in the dev DB resets the counters.
- **Port 5433 is taken:** change the mapping in `docker-compose.dev.yml` and `DATABASE_URL`.
- **Startup exits with "Invalid environment configuration":** fix the listed variables in `.env`.
